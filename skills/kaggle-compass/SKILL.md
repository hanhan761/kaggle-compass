# 指南针

以“误差需求 → 社区能力匹配 → 融合或开发 → 批量验证 → 更新画像”为循环。用户说“指南针”即触发；技术名 kaggle-compass，显式调用 $kaggle-compass。

## 两种向量，两个用途

- **代码检索向量**：按功能模块拆分 Notebook，关联源码、权重、数据、父方案和内容哈希。用于检索与同源识别，不能证明性能。内置工具为确定性词法/AST 哈希向量，不是训练好的语义 encoder；真正语义检索可接入固定版本外部 embedding，记录模型、池化、维数和归一化。
- **实测能力向量**：在同一评估批次、基线及指标下，各固定误差组的平均指标增量。负值保留，未知不能填零。需求与能力共享组定义、顺序及版本。
- 不直接计算原始代码向量和误差向量的夹角；两者没有共同空间。语义相似度只决定筛选优先级。

## 工作方法

1. 读取项目 AGENTS.md、版本清单和明确版本记录；保持稳定基线。工具、文档版本与比赛预测版本分别管理。遵守计算、隐私及提交授权边界。
2. 批量整理全部分子误差：候选未召回、截断、排序及模拟器支持/未送入/评分失败分别记录。统计分母；聚类只用无答案特征拟合。标签用于事后分析，不能用于未知样本门控。
3. 建立模块注册表：确切来源版本、license、代码哈希、权重哈希、候选库版本、父方案、阶段及成本。缺失信息标记 unknown。公开可访问不等于已确认许可。共享权重和资产的分支不能作为独立证据重复投票。
4. 用代码索引筛选，再在固定开发/校准批次实测。比较救回、伤害、候选独有覆盖、各组指标增量及按独立结构/骨架块计算的区间。最终排名文件无法给出完整候选召回，不能混称。
5. 候选缺失优先研究召回/生成；候选存在但排名低优先研究证据/重排。保留单独得分低但互补的组件，也根据未覆盖需求自行开发。每个假设规定验证与停止条件。
6. 简单融合先检验互补，再考虑 OOF 预测训练排序器或 Transformer。不同量纲原始分数不直接平均。按评分键去重；完整融合重放与正式预测一致；消融复用资产。单组件能力不能替代真实融合后能力。
7. 校准组冻结策略后才打开独立确认组。反复使用的确认组变成开发证据。记录预训练暴露未知及领域差异，不把代理验证当隐藏测试分数。
8. 交付主要失分、实测/推测能力、融合/开发/暂缓原因、净收益区间、成本及下一轮实验。用可核验版本与批次更新画像；公开榜仅作外部验证之一。长任务接入用户要求的提醒并保留检查点。

## 工具入口

建立输入或评估时读 [references/contracts.md](references/contracts.md)。

scripts/compass.py 提供 index / search / profile / compare：

- index：不执行 Notebook，提取模块并生成可复现检索向量。
- search：在相同 encoder 空间检索，支持带来源记录的外部模块向量。
- profile：从基线排名建立需求画像；输入来自答案分析阶段。
- compare：严格对齐查询、基线、批次及指标，计算能力向量与配对块 bootstrap；建议只表示实验优先级，不自动接入预测或提交。

合成示例只验证工具，不是比赛成绩。大规模分析遵循项目计算配置。无数据时完善契约并登记待测方案，不能编造收益或因 embedding 相似就自动融合。
